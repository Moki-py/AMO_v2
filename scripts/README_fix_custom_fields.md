# Скрипт исправления кастомных полей AmoCRM

Этот скрипт исправляет существующие данные в MongoDB, добавляя дружелюбные названия кастомных полей на основе `field_name` из AmoCRM HAL формата.

## Проблема

До исправления кастомные поля имели технические названия:
- `custom_field_2010696`
- `custom_field_2010697`

После исправления появляются дружелюбные названия:
- `источник_маркер` (из "Источник (Маркер)")
- `бюджет_клиента` (из "Бюджет клиента")

## Требования

- Python 3.7+
- pymongo
- Доступ к MongoDB с данными AmoCRM

## Установка зависимостей

```bash
pip install pymongo
```

## Использование

### 1. Просмотр изменений (Dry Run)

Сначала **обязательно** запустите в режиме просмотра, чтобы увидеть, что будет изменено:

```bash
python scripts/fix_custom_fields_inplace.py --dry-run
```

### 2. Создание backup и применение изменений

```bash
python scripts/fix_custom_fields_inplace.py --fix --backup
```

### 3. Применение изменений без backup (не рекомендуется)

```bash
python scripts/fix_custom_fields_inplace.py --fix
```

## Параметры

### Обязательные (выберите один):
- `--dry-run` - Показать что будет изменено без изменения данных
- `--fix` - Применить исправления к данным

### Опциональные:
- `--backup` - Создать backup коллекций перед изменениями
- `--collections deals contacts companies` - Указать конкретные коллекции
- `--mongodb-uri mongodb://localhost:27017` - URI подключения к MongoDB
- `--database amocrm_data` - Имя базы данных

## Переменные окружения

Вы можете использовать переменные окружения вместо параметров:

```bash
export MONGODB_URI="mongodb://username:password@host:port"
export MONGODB_DB="amocrm_data"
```

## Примеры использования

### Проверить изменения для конкретных коллекций
```bash
python scripts/fix_custom_fields_inplace.py --dry-run --collections deals contacts
```

### Исправить только сделки с backup
```bash
python scripts/fix_custom_fields_inplace.py --fix --backup --collections deals
```

### Подключение к удаленной MongoDB
```bash
python scripts/fix_custom_fields_inplace.py --dry-run \
  --mongodb-uri "mongodb://user:pass@host:27017" \
  --database "amocrm_production"
```

## Что делает скрипт

1. **Подключается к MongoDB** и проверяет доступные коллекции
2. **Находит документы** с полем `custom_fields_values`
3. **Обрабатывает каждое кастомное поле**:
   - Извлекает `field_name` и `field_id`
   - Санитизирует `field_name` для использования как ключ
   - Создает новые поля с дружелюбными названиями
4. **Обновляет документы** в MongoDB (при `--fix`)
5. **Создает backup** (при `--backup`)

## Логика санитизации имен полей

```
"Источник (Маркер)" → "источник_маркер"
"Бюджет / Сумма"   → "бюджет_сумма"
"Тип [Услуги]"     → "тип_услуги"
```

Удаляются символы: `()[]/_\-` и пробелы заменяются на `_`

## Обратная совместимость

Скрипт добавляет новые поля, но **НЕ удаляет** старые `custom_field_*` поля, обеспечивая обратную совместимость.

## Результат выполнения

### Single-value поля
```json
{
  "custom_field_2010696": "Яндекс Директ",     // старое (остается)
  "источник_маркер": "Яндекс Директ"           // новое (добавляется)
}
```

### Multi-value поля
```json
{
  "тип_услуги_0": "Консультация",
  "тип_услуги_1": "Разработка",
  "тип_услуги_all": "Консультация; Разработка",
  "тип_услуги_count": 2
}
```

## Безопасность

⚠️ **ВНИМАНИЕ**: Скрипт изменяет данные в MongoDB!

**Рекомендуемый порядок:**
1. Сначала `--dry-run` для проверки
2. Затем `--fix --backup` для безопасного применения
3. Проверить результаты в приложении

**Создание backup:**
- Создается коллекция `{collection_name}_backup_{timestamp}`
- Содержит полную копию данных до изменений
- Можно восстановить данные при необходимости

## Восстановление из backup

В случае проблем:

```javascript
// В MongoDB shell
db.deals_backup_20241201_143022.find().forEach(function(doc) {
    db.deals.replaceOne({_id: doc._id}, doc);
});
```

## Устранение неполадок

### Ошибка подключения к MongoDB
```
❌ Ошибка подключения к MongoDB: ...
```
**Решение:** Проверьте URI подключения и доступность сервера

### Нет документов с кастомными полями
```
🔍 Коллекция deals: документы с кастомными полями не найдены
```
**Возможные причины:**
- Данные еще не синхронизированы из AmoCRM
- Кастомные поля хранятся в другом формате
- Коллекция пустая

### Ошибки обработки документов
```
❌ Ошибка обработки документа 12345: ...
```
**Решение:** Проверьте структуру данных, скрипт продолжит с другими документами
