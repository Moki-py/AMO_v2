# Исправление обработки кастомных полей AmoCRM

## Проблема

В системе экспорта данных AmoCRM кастомные поля отображались с техническими названиями вида `custom_field_2010696` вместо понятных имен полей из `field_name`, например:

**До исправления:**
- `custom_field_2010696` вместо "Источник (Маркер)"
- `custom_field_2010697` вместо "Бюджет клиента"

**После исправления:**
- `источник_маркер` (из field_name "Источник (Маркер)")
- `бюджет_клиента` (из field_name "Бюджет клиента")

## Структура данных AmoCRM HAL

AmoCRM предоставляет данные в HAL формате, где кастомные поля содержат:

```json
{
  "custom_fields_values": [
    {
      "field_id": 2010696,
      "field_name": "Источник (Маркер)",
      "field_code": null,
      "field_type": "text",
      "values": [
        {
          "value": "Яндекс Директ"
        }
      ]
    }
  ]
}
```

## Внесенные изменения

### 1. data_enrichment.py

**Метод `flatten_custom_fields()`:**
- Изменен приоритет: сначала `field_name`, затем cached mapping, и только в конце fallback к `field_id`
- Улучшено сообщение об ошибке

**Метод `_flatten_field_values()`:**
- Добавлена санитизация `field_name` для создания валидных имен колонок
- Создание primary_key на основе `field_name` с fallback к `field_id`
- Сохранение обратной совместимости через дублирование с `custom_field_{id}`

### 2. excel_exporter.py

**Метод `_process_custom_fields()`:**
- Приоритизация `field_name` над `field_id` для названий колонок
- Улучшенная обработка случаев, когда `field_name` отсутствует
- Санитизация названий колонок для совместимости с Excel

### 3. sheets_exporter.py

**Метод `_process_data_efficient()`:**
- Аналогичные изменения для Google Sheets экспорта
- Приоритизация `field_name` при создании названий колонок

## Логика приоритизации

1. **Первый приоритет:** `field_name` из данных AmoCRM
   - Санитизируется для безопасного использования как имя колонки
   - Удаляются специальные символы: `()[]/_\-`
   - Приводится к нижнему регистру

2. **Второй приоритет:** Cached mapping (data_enrichment.py)
   - Используется кэшированная информация о полях

3. **Fallback:** `custom_field_{field_id}`
   - Используется только когда `field_name` недоступно

## Обратная совместимость

Система сохраняет обратную совместимость:
- Создаются поля с дружелюбными именами (primary)
- Дублируются поля с техническими именами (для старых экспортов)
- Это позволяет постепенно мигрировать на новую систему именования

## Примеры результата

**Для поля:**
```json
{
  "field_id": 2010696,
  "field_name": "Источник (Маркер)",
  "values": [{"value": "Яндекс Директ"}]
}
```

**Создаются колонки:**
- `источник_маркер`: "Яндекс Директ" (основная, дружелюбная)
- `custom_field_2010696`: "Яндекс Директ" (для совместимости)

✅ Улучшена читаемость экспортированных данных
